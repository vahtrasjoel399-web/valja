# Valentina Šestero — сайт фотографа

Статическая страница + Vercel Function `/api/portfolio`. Админка открывается тремя быстрыми нажатиями на логотип. Сначала показаны все существующие фото портфолио. «Удалить» убирает фото из галереи для всех посетителей; «Отменить удаление» возвращает последнее удалённое фото в текущей сессии страницы.

## Включение удаления на опубликованном сайте

1. В проекте Vercel откройте **Storage** и подключите **Neon (Postgres)** к окружению **Production**. Нужна pooled connection string: интеграция должна добавить `DATABASE_URL` или `POSTGRES_URL`. При ручной настройке используйте адрес Neon с `-pooler` в имени хоста. Код использует существующую зависимость `@vercel/postgres`.
2. В **Settings → Environment Variables** для Production задайте:
   - `ADMIN_USER` — имя для входа;
   - `ADMIN_PASSWORD` — новый пароль (старый пароль из JavaScript больше не используется);
   - `SESSION_SECRET` — случайная строка длиной не менее 32 символов. Например, её можно создать командой `openssl rand -hex 32`.
3. Опубликуйте изменения и выполните **Redeploy** после добавления переменных. Настройки сборки берутся из `vercel.json`: `npm run build`, output directory `public`. Не переопределяйте их старой статической командой в настройках проекта.
4. Откройте `/api/portfolio`: после настройки ответ должен содержать `"configured": true`. Войдите в админку и проверьте удаление и отмену в отдельном приватном окне. Таблицы создаются автоматически при первом запросе; SQL вручную запускать не нужно.

Если база или переменные входа не настроены, админка объясняет причину и не выполняет удаление. Если настроенная база недоступна, сайт показывает ошибку загрузки фотографий и кнопку повтора, чтобы случайно не вернуть удалённые фотографии.

Официальные инструкции: [Storage на Vercel](https://vercel.com/docs/marketplace-storage), [подключение Neon к Vercel](https://neon.com/docs/guides/vercel-manual), [Vercel Functions](https://vercel.com/docs/functions/runtimes/node-js).

## Что сохраняется

- Удаления исходных фото сохраняются в таблице `site_hidden_photos`, переживают перезагрузки и деплои и применяются ко всем новым загрузкам галереи. Открытая вкладка обновляет список при возвращении к ней.
- Это удаление из портфолио: исходный файл остаётся в репозитории и доступен по прямому URL. Для полного удаления файла нужно отдельное изменение репозитория и деплой.
- Старые удаления из localStorage не публикуются автоматически. После перехода на серверное хранение выбранные фото нужно удалить в админке заново.
- Локально добавленные фотографии пока остаются локальными: они явно помечены «Локально», а форма находится в раскрывающемся блоке. Этот код не подключает облачную загрузку новых файлов.
- Пароль проверяется на сервере; сессия использует HttpOnly-cookie. При смене пароля или SESSION_SECRET старые сессии перестают действовать.

## Разработка и проверки

Статическая страница использует готовый `assets/tailwind.css` вместо внешнего
Tailwind CDN. После изменения utility-классов в HTML/JavaScript или темы в
`tailwind.static.cjs` выполните `npm run build:css`, затем `npm run build`.
Сгенерированный CSS хранится в репозитории, поэтому локальный просмотр работает
без скачивания Tailwind в браузере. Google Fonts подключаются без блокировки
первого отображения страницы.

Node.js 22.9+:

```sh
npm install
npm run dev
npm test
npm run build
```

Для подключения тестовой базы скопируйте `.env.example` в `.env.local` и заполните переменные. Без переменных локальная галерея показывает исходные фотографии, а серверные изменения отключены. Локальный сервер слушает только `127.0.0.1:3000`; после изменения файлов его нужно перезапустить.

Сборка копирует только HTML, CSS, клиентский JavaScript и assets в `public/`. Код сервера, тесты и переменные окружения туда не попадают. Функция Vercel находится отдельно в `api/`.

`npm test` проверяет обработчики интерфейса и API с имитацией DOM и общей тестовой базой в памяти. Проверяются удаление/отмена между независимыми посетителями, ошибки сети/хранилища, доступ, CSRF, ограничение входа и переводы. Это не проверка подключения к настоящему Postgres или визуального вида в браузере.

При добавлении исходных фото обновите список в `script.js` и `server/portfolio-ids.json`: тест сверяет их, чтобы сервер разрешал управление всеми фото портфолио.
